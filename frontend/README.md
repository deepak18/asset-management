# Frontend — Asset Management Terminal

Next.js (App Router) + TypeScript dashboard for the local investment-research
platform. The browser talks to the backend **only** through the versioned REST
API — there is no shared code or DB access. The API contract
(`../backend/openapi.json`) is the single source of truth: TypeScript types are
generated from it, and the UI is built and tested against **MSW mocks** so it
never blocks on a live backend.

## Stack

| Concern        | Choice                                                      |
| -------------- | ----------------------------------------------------------- |
| Framework      | Next.js 16 (App Router, Turbopack)                          |
| Language       | TypeScript 5 (strict, `noUncheckedIndexedAccess`, no `any`) |
| Styling        | Tailwind CSS 3 + shadcn/ui-style primitives                 |
| Charts         | Recharts (donut allocations)                                |
| Contract types | `openapi-typescript` → `src/types/api.ts`                   |
| Mock layer     | MSW (`msw/node` in tests, `msw/browser` in dev)             |
| Tests          | Vitest + React Testing Library (jsdom)                      |

## Mock-first, then live

The UI is developed against the contract, not a running backend:

1. **Mock mode (default for local UI work).** Set `NEXT_PUBLIC_API_MOCKING=enabled`.
   MSW intercepts every request in the browser and serves fixtures from
   `src/mocks/` shaped by the generated contract types. Tests always run this way
   (via `msw/node`), so the suite needs no backend.
2. **Live mode.** Unset `NEXT_PUBLIC_API_MOCKING` (or set it to anything else) and
   point `NEXT_PUBLIC_API_BASE_URL` at the running FastAPI server. The typed API
   client (`src/lib/api-client.ts`) is the only thing that changes behavior — the
   components don't know the difference.

**When the backend publishes a new `openapi.json`:** run `npm run typegen`,
fix any resulting type errors, then update/remove the matching MSW handler in
`src/mocks/handlers.ts` (and its fixture) as endpoints go live. The generated
`src/types/api.ts` is tool-owned — never hand-edit it.

The MSW browser worker file (`public/mockServiceWorker.js`) is generated by
`npx msw init public/ --save` and is git-ignored; re-run that once after a fresh
clone if you use browser mock mode.

## Run the full stack locally (live mode)

Live mode is the zero-config default: with no `.env.local` (or with
`NEXT_PUBLIC_API_MOCKING` unset), the client calls the real API at
`NEXT_PUBLIC_API_BASE_URL` (default `http://localhost:8000`).

```powershell
# terminal 1 — backend API (see ../backend/README.md)
cd ../backend
uv run uvicorn app.main:app --reload      # http://localhost:8000/docs

# terminal 2 — this app, live
cd frontend
npm run dev                               # http://localhost:3000
```

Both backend-side prerequisites are now in place, so live mode works end-to-end:

1. **CORS** allows the dev origin `http://localhost:3000` — the backend enables
   config-driven CORS for it, so the browser's cross-origin `GET`s go through.
2. **Portfolio selection** — the dashboard lists portfolios and uses the selected
   id for its transactions, holdings, and analytics. An empty database prompts
   you to create a portfolio; no seeded id is required.

## How the money model works (important)

The backend serializes all monetary/quantity/weight/rate values as **Decimal
strings** (never floats). The UI honors that end-to-end:

- `src/lib/decimal.ts` parses/rounds/scales those strings **without** `Number`
  arithmetic, so no float rounding error ever reaches a displayed figure.
- `src/lib/format.ts` renders them (`formatMoney`, `formatPercent`) and shows an
  em dash (`—`) — never a fabricated `0` — for null/unpriced/undefined values.
- Charts use a float **only** to size an SVG wedge; every number the user reads
  is formatted from the original string.

## Routes and account workflow

| URL | Purpose |
| --- | --- |
| `/` | Automatic account overview: reported holdings for a nonempty snapshot or known retirement type; otherwise ledger analytics. Loading/errors never become a zero balance. |
| `/holdings` | Reported holdings only, including honest empty/partial states and source provenance. |
| `/ledger` | Trade-ledger summary, allocations, holdings/history, transactions, watchlist and manual entry. No statement import forms or account settings. |
| `/imports` | Choose **Robinhood** or **Vanguard** in the Brokerage selector. Only that brokerage's existing form and history are mounted. |
| `/settings` | Selected account metadata with explicit Edit/Save/Cancel. **Taxable Brokerage** uses the existing `TAXABLE` value and means an ordinary non-retirement investment account, not a 401(k) or IRA. |
| `/portfolios/{id}/holdings/{ticker}` | Existing URL-scoped holding detail. Back to portfolio targets `/ledger?portfolio={id}`. |

The persistent layout owns the portfolio picker and theme toggle. Primary navigation
uses real Next links with `aria-current="page"`, keyboard focus styles, wrapping
small-screen layout and a skip-to-content link. Feature links include
`?portfolio={id}` for bookmarking; query selection overrides stored selection on
route/query entry, including browser history changes, but is not reapplied after
same-page metadata refreshes or picker changes. Invalid/unknown query IDs retain the
normal stored/first-account fallback. Holding-detail navigation uses the URL account,
not an unrelated picker selection.

Import workflow: select the destination portfolio, open **Imports**, choose the
brokerage, then upload. Robinhood retains its asynchronous 202/poll/history and
explicit duplicate-override workflow. Vanguard retains preview, unchecked review
acknowledgement and strict confirmed commit. After success the shared refresh token
and portfolio list update, the mounted import history/activity reload, and a result
link opens **Ledger Analytics** or **Reported Holdings**. Destination pages read
fresh data when mounted; imports are not embedded in either data page.

Same-account refreshes preserve open editors, drafts and history-trigger identity.
Account, route and brokerage changes unmount obsolete work and reset local upload
state. Vanguard transport aborts on unmount and ignores stale responses. The unchanged
Robinhood uploader does not abort an already-submitted POST, but detached results
cannot start a new mounted poller or refresh the newly selected scope; polling stops
on unmount. Browser cancellation cannot undo server writes: inspect history before
resubmitting an abandoned import.

Page ownership lives in `components/portfolio/dashboard.tsx`,
`portfolio-boundary.tsx` (query/selection/loading/error/empty and metadata refresh),
`imports-page.tsx` (one brokerage at a time) and
`components/app-shell/portfolio-links.tsx` (shared destinations).
`feature-pages.test.tsx` mounts actual route modules using a thin Next navigation
harness; existing financial/history/draft regressions remain active on their owning
surfaces. Long workflows are split by responsibility, not given larger timeouts.
The contract, generated API/domain types and both import forms are unchanged; no
`typegen` is needed for this navigation-only slice.

## Portfolio selection, data entry & statement import

The dashboard is no longer pinned to a single portfolio id:

- **Picker (app shell).** `GET /api/v1/portfolios` populates a dropdown in the nav.
  The chosen id is persisted in `localStorage` (`am.selected.portfolio`) and shared
  through a React context (`hooks/use-portfolio-selection.tsx`), so every panel
  reads the selected portfolio. With **no portfolios** the UI prompts to create one.
- **Create portfolio.** `POST /api/v1/portfolios` from a dialog, then the new
  portfolio is auto-selected.
- **Add position (snapshot).** `POST /api/v1/portfolios/{id}/positions` — cost basis
  is entered as _exactly one_ of per-share or total (the "both" case is
  unrepresentable in the form, so the 422 can't happen); the form spells out that a
  snapshot leaves XIRR undefined until full history is imported.
- **Manual transaction.** `POST /api/v1/portfolios/{id}/transactions` with only the
  fields relevant to the chosen type (BUY/SELL → qty/price/fees, DIVIDEND/FEE →
  amount, SPLIT → ratio). Bodies use the **`Transaction`** input schema; ledger GET uses `TransactionRecord`.
- **CSV import (async).** `POST .../imports` (multipart, expects **202**) →
  poll `GET .../imports/{job_id}` ~1s until `SUCCEEDED`/`FAILED` (polling stops on
  terminal state **and** on unmount — no leaked intervals). Progress is
  indeterminate until `total_rows` is counted. On success we show
  `created_transactions`, `tickers`, and every `warnings[]` row that needs manual
  entry; `409` (duplicate) offers an explicit "import anyway"
  (`allow_duplicate=true`), `413`/`422` are explained.

After a successful write or import, a shared `dataVersion` token invalidates
selected-account reads. Mounted panels refetch; other routes read fresh data on entry.

> **Contract note:** these routes came from a backend contract bump. Regenerate
> types with `npm run typegen`, then reconcile the MSW handlers/fixtures in
> `src/mocks/`. POST uses `Transaction`; ledger reads use `TransactionRecord`.

## Holdings: inspect, classify, and correct

- The dashboard holdings table links each ticker to
  `/portfolios/{id}/holdings/{ticker}`. The URL, not the locally selected id,
  identifies the detail page's portfolio. **Back to portfolio** restores that
  portfolio on `/ledger?portfolio={id}`.
- Warning icons include readable explanations from the API's typed `data_gaps`.
  Missing prices are a separate provider-availability message, not a manual
  classification field. Other ledger gaps direct you to review source history;
  the sector/industry editor does not repair transactions or cost basis.
- Sector and industry cells have pencil buttons in both views. Save PATCHes only
  that ticker and field; Cancel changes nothing. Blank explicitly sends `null`
  to clear a label. Inputs follow the contract's 80-character limit. A failed
  save preserves its draft and displays a local error; refreshing another cell
  does not discard an open draft.
- Sector/industry editors suggest existing values of the **same field** from all
  holdings in that portfolio, including the current holding. Matching is a
  case-insensitive substring search. Values are trimmed, nonempty, deduplicated
  case-insensitively (first existing spelling retained), and sorted by lowercased
  text. No hardcoded taxonomy or other portfolio's labels are used.
  Arrow keys navigate; Enter selects without submitting. Clicking an option fills
  the draft only. Escape closes suggestions without reaching an enclosing modal;
  blur and outside clicks also dismiss them. Free text and blank clears remain
  supported, with explicit Save/Cancel actions.
  The table reuses its full holdings read; detail uses one `useHoldings` read for
  the URL portfolio, refreshed on the existing save/history/ledger version token.
  Loading or failed suggestions never block editing or discard drafts, and stale
  responses after portfolio switches or unmount are ignored.
- The detail page displays available position values, classification provenance,
  gap warnings, and ticker-filtered transactions. Company names, live-price
  inputs, average-cost calculations, and research are not fabricated. It now shows
  **this holding's own** annualized money-weighted return (XIRR), scoped to the
  URL portfolio + ticker — not the portfolio-wide figure. The backend computes it
  from the ticker's own dated cash flows, so an unrelated holding's missing price
  or FX rate cannot suppress it.
- A computed return uses the existing percentage conventions (legitimate zero and
  negative values included) and shows its valuation provenance: a live quote's
  `provider_code`/`source_table`/as-of for open positions, or the final ledger
  date for closed ones. It never invents metadata the backend did not supply.
- The holding return stays `—` when the backend withholds it, with status-specific
  guidance (never a fake 0): `UNPRICED_POSITION` → **Connect market data**;
  `INCOMPLETE_HISTORY` → review/repair full broker-record history, add or import
  missing dated transactions, then explicitly confirm; `INSUFFICIENT_FLOWS` → **Needs more history**; `MISSING_FX` → add
  the exchange rate; `INVALID_HISTORY` → review source history. Loading, request
  failure, and 404 of the return never disable classification editing or the
  ledger. Portfolio-wide XIRR on the dashboard is unchanged.
- **Classify holdings**, above the table, follows `next_cursor` as `after_ticker`
  until `remaining=0`, including unsuccessful lookups. A fresh click starts a
  fresh sweep and retries unresolved tickers. Manual labels (even cleared ones)
  remain protected; this UI does not request `refresh=true`.
- HTTP **503** means missing configuration: set the backend's
  `ALPHAVANTAGE_API_KEY` and verify `ALPHAVANTAGE_MCP_URL`; never expose these as
  `NEXT_PUBLIC_*` variables. The action is replaced by setup guidance, not retry.
  Once configuration is fixed, reload the page. HTTP **200** can still report
  `PROVIDER_UNAVAILABLE` failures (quota/outage), which suggest trying later.
  `NO_PROFILE` suggests manual entry or a later sweep, not permanent failure.
- Successful edits/classification refresh dashboard data. Detail saves use the
  committed PATCH response for labels and refetch analytics/transactions. New
  allocation labels appear when prices are available; editing labels cannot
  supply missing prices. Allocation donuts and legends are **reporting only**.

## Holding history and deleting ledger events

The dashboard's main Holdings table shows **History not confirmed** with inline,
readable reasons when the API reports `history_complete=false`. It is independent
of pricing, classification gaps and XIRR availability; `true` means no *known*
blocker under backend policy, not independently verified broker history. Reasons
include unknown origin, synthetic snapshots, incomplete or unfinished imports,
unresolved source events, deliberately deleted transactions, no active transactions,
and no acquisition. Several may apply at once.

Both the holdings table and holding detail offer **Review history**, including
for naturally complete history. The accessible dialog fetches a scoped snapshot
using `GET /api/v1/portfolios/{portfolio_id}/holdings/{ticker}/history` and shows
all active ledger rows (stable IDs, original decimal strings and explicit row
currency), history gaps and backend `blocking_gaps`. No UI financial calculation
or local completeness policy is used.

Compare the snapshot against actual broker records, including acquisition dates,
quantities, costs, fees, dividends, other cash events and splits. **Add missing
transaction** reuses the manual form (BUY/SELL/DIVIDEND/FEE/SPLIT), with the ticker
prefilled and locked and the portfolio base currency as the default. Never guess
history. A synthetic opening snapshot is not an actual purchase: add the actual
records, then follow the scoped detail-ledger link and use existing confirmed
deletion to remove the synthetic row. Unresolved source events and failed imports
must be repaired/retried through existing import surfaces or correction APIs;
checking a box does not fix blockers. Reload the review after those repairs.

Confirmation requires an initially unchecked, explicit broker-record attestation,
a loaded snapshot, no backend blockers and no pending write. It POSTs only
`{review_token, confirmed: true}` to the same history path. A 409 clears the
acknowledgement and token and fetches fresh history with a visible change notice;
it never automatically retries confirmation. Other failures remain retryable,
and failed transaction entry preserves its draft. Repairs clear acknowledgement
and reload the review and affected holdings, analytics/XIRR, ledger and dashboard
siblings while the dialog remains open. Closing, Escape and portfolio changes
never initiate confirmation; late responses cannot refresh another scope.
Already-submitted writes may still commit server-side despite browser cancellation.

**History complete** without `confirmed_at` means naturally complete under backend
policy, not explicitly broker-verified. Explicit confirmation shows the response's
timestamp and remains inspectable when reopened. Ledger/import changes invalidate
saved confirmations. Confirmation never supplies missing prices/FX or fabricates
an XIRR. Live deployments require the backend history-confirmation migration
`0008` (see `backend/README.md`). API types are regenerated from the checked-in
OpenAPI contract; minimal deterministic MSW state emulates confirmation/token
invalidation for tests, not the full backend history/replay policy.

New scoped UI: `src/components/portfolio/holding-history-review.tsx`.
Regression coverage: `src/__tests__/components/holding-history-review.test.tsx`
and `src/__tests__/lib/holding-history-api.test.ts`.

Both dashboard and filtered holding ledgers use stable `TransactionRecord.id` values,
not display order or matching financial fields. Delete opens a keyboard-accessible
confirmation naming the event and account. Cancel, Escape or dismiss does nothing;
confirm calls `DELETE /api/v1/portfolios/{portfolio_id}/transactions/{id}`. `204`
has no response body. `404` means a stale/wrong-account row and triggers a refetch;
`409` keeps the row with the backend's conflict explanation (e.g. dependent sales or
active imports). Network/server failures also keep the row. Successful deletion
refreshes ledger, holding history, dashboard analytics/allocations and import history;
filtered holding detail refetches its return. A tracked holding survives deletion of
its last event without a calculated position. There is no undo; the server retains
an audit tombstone and may disable import retry. Live backend deployments must
apply migration `0007` before enabling this UI (see `backend/README.md`).

## Read-only row provenance, labels, deletion identification and unchanged write payloads

The review table and normal transaction ledger have an **Origin** column,
read directly from required `TransactionRecord.history_origin` (`LedgerOrigin`):
**Observed event** (`OBSERVED`), **Synthetic snapshot** (`SNAPSHOT`), or
**Legacy / unverified** (`UNKNOWN`). Deletion confirmation also names the selected
stable transaction ID and origin, so the synthetic opening row can be identified
without guessing from its date, type or price. Observed origin does **not** mean
complete or independently verified history; API history diagnostics and blockers
remain authoritative. Origin and identity are read-only: `Transaction` write
payloads do not include them. Manual/observed mock events use `OBSERVED`; internal
synthetic seed events explicitly use `SNAPSHOT`, and only legacy seeds use `UNKNOWN`.
The mock token includes each row's origin, so origin changes invalidate it.

Shared labels: `src/components/portfolio/ledger-origin.ts`. Mixed-origin row IDs,
deletion provenance and strict writes are covered by
`src/__tests__/components/ledger-origin.test.tsx`. Review regressions also cover
late GET responses after close/account switch and detail-ledger/XIRR refresh after
adding a missing dividend while the review remains open.

## Allocation donut interactions

Allocation remains read-only reporting: selecting a category does not edit labels,
filter holdings, fetch market data, or write to the API. Hover a wedge or hover/focus
its legend button to preview category, market value and percentage in the anchored
detail card, plus every current holding in that category and its backend ticker
weight labeled **% of portfolio**. No within-category percentages are calculated.
The matching legend gains a border/background and the active wedge
expands with a foreground stroke; other wedges dim slightly. Click/tap a wedge or
legend button to pin; selecting the same category unpins. Other hover/focus previews
return to the pinned category on leave/blur. Native Enter/Space activates legend
buttons (`aria-pressed`); Escape or **Clear Selection** resets the chart. Clear
restores focus to the selected legend button without reopening the preview.

The detail card uses light/dark popover tokens and stable description IDs. Legend
buttons expose all values to keyboard/screen-reader users; the equivalent SVG is
decorative, not a second keyboard navigation system. No live region repeats every
pointer movement. Recharts animation is disabled; small CSS transitions honor
reduced motion. No center text competes for the 160px donut's limited space.
Original Decimal strings feed existing formatters; floats size arcs only. Zero or
non-renderable weights retain usable, honestly labeled legend entries. Empty
allocations retain the existing unavailable message and no ring.

Sector/industry states are independent. Refreshing chart props reconciles selection
by category key and drops removed categories. The data wrapper is keyed by portfolio
so neither previous data nor selection carries across accounts. Its existing loading
state remounts charts during a network refresh (pins reset on that refresh).

### Allocation holding membership and pricing limits

- The section reuses `useHoldings` / the typed REST client for **one holdings read
  per portfolio + refresh generation**, shared by both charts; hovering does not
  fetch. Analytics and holdings start together. A generation-keyed remount clears
  both old resources immediately, and the existing hook ignores abandoned responses.
  A slow holdings read shows a list-only loading message; failure shows a list-only
  error while wedges, legend and selection remain usable. The next dashboard
  refresh retries both reads. These separate GETs are not an atomic server snapshot;
  an out-of-band concurrent edit cannot be detected without a backend version seam.
- Membership joins `PortfolioAnalytics.positions` to `HoldingInfo` by exact ticker.
  Only backend `open_quantity > 0` positions participate (decimal sign inspection,
  not a quantity/valuation calculation); closed positions and holdings with no
  calculated position are excluded. Missing metadata, null and empty labels use
  `UNCLASSIFIED`, exactly like the backend's `label or UNCLASSIFIED`. Labels are
  **not** trimmed or case-folded; a literal `UNCLASSIFIED` joins the same bucket.
- Each ticker's displayed weight comes unchanged from `allocation_by_ticker.weight`
  through `formatPercent`. Missing weights stay a dash with **Weight unavailable**;
  `unpriced_tickers` adds an explicit unpriced status. Unpriced category members are
  not silently filtered out because they lack allocation rows.
- The backend service computes allocations from successfully priced open positions
  only, excluding missing quotes/FX from its denominator. If `unpriced_tickers` is
  nonempty, a visible notice explains that **% of portfolio** means the backend's
  priced subset, not the full book. This UI does not renormalize or fill gaps.
  Entirely unpriced categories have no slice; empty allocations retain the existing
  unavailable state rather than synthesizing categories or zero weights.
- Lists retain all entries, sorted by ticker, in a responsive bounded-height,
  keyboard-focusable scroll region with named semantic lists. Pin before scrolling
  so leaving a preview does not dismiss it. Escape/Clear remove the list; temporary
  pointer/focus previews restore the pinned category's list. There is no hover live
  region repeatedly announcing the whole list.
- Consumed contract: `GET /api/v1/portfolios/{portfolio_id}/analytics` and
  `GET /api/v1/portfolios/{portfolio_id}/holdings`. Checked-in OpenAPI publishes
  200/422 for these GETs; runtime analytics additionally returns 404 when absent
  (handled as a read error). Holdings collection directly returns its provider list,
  not the single-holding endpoint's documented 404. No contract/typegen change.

## Button naming and confirmation dismissal

Button text and icon-button accessible names use explicit Title Case, including
short words such as **For**, **Of** and **To** (for example, **Review History**,
**Confirm History**, **Reload History / Retry**, and **Close Dialog**). Pending
labels retain their ellipses. Do not apply CSS or runtime case conversion to
arbitrary children: tickers, acronyms, IDs, names and API values keep their casing;
ordinary prose, headings and navigation links are not part of this convention.

A successful, non-aborted history-confirmation POST refreshes the affected parent
views and closes the review, restoring focus to its trigger. It does not reload
a review that is being dismissed. Reopening fetches persisted history, including
the server's confirmation timestamp. HTTP/network errors keep the dialog open;
a 409 still reloads history, clears acknowledgement and never automatically
resubmits. Adding a missing transaction remains a repair: refresh and reload while
keeping the review open. Regression coverage includes
`src/__tests__/components/history-confirm-dismissal.test.tsx` and
`src/__tests__/components/button-labels.test.tsx`.
